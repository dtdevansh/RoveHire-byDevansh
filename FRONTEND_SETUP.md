# Claude Code — Frontend Setup Guide (Rove Hire)

Scaffold the **Rove Hire** frontend: Next.js (App Router) + TypeScript + Tailwind, with the
state layer, API client, Supabase auth wiring, theme tokens, and folder structure all
standing and compiling. **Do not build page UIs in this pass** — create route stubs that
render a placeholder and compile clean. Pages get built later against `UI_GUIDE.md`.

Companion docs (treat as source of truth):
- `UI_GUIDE.md` — theme tokens (Part 1) to wire into Tailwind. Do not restyle pages yet.
- `BACKEND.md` — the REST API contract + model shapes to mirror in `types/`.

Work in phases, in order. Each phase ends green before the next starts.

---

## 0. Operating rules

1. **TypeScript strict.** `strict: true`, no `any`, no `@ts-ignore`, no `@ts-expect-error`
   left in committed code.
2. **No comments.** Self-documenting code; remove scaffold/boilerplate comments generated by
   tooling. (Mirrors the backend rule — loosen only if the user says so.)
3. **No dead code / unused deps.** Every dependency installed is used by end of setup.
4. **No secrets committed.** `.env.local` is gitignored; only `.env.local.example` is
   committed. No keys hardcoded anywhere.
5. **Do not build the visual pages.** Route files render a minimal placeholder only. The
   goal of this guide is a compiling skeleton, not screens.
6. **Conventional commits**, small and scoped.
7. If a version/flag has changed since this guide and a command errors, adapt minimally and
   note it in the final report — don't silently swap architecture.

---

## 1. Prerequisites & repo/branch

- Node.js LTS (≥ 20). Verify `node -v` and `npm -v` first.
- The user will paste the **GitHub repo URL** in chat. Use that as `<REPO_URL>`.

Repo/branch setup (the frontend lives at repo root or in a `frontend/` dir — default to a
`frontend/` subfolder unless the user says the repo is frontend-only):

```bash
git clone <REPO_URL> rove-hire
cd rove-hire
git checkout -b frontend
```

If the repo is empty/new and clone gives nothing to check out, `git init`, add the remote
(`git remote add origin <REPO_URL>`), then create the branch. Confirm the working branch is
`frontend` before committing anything.

---

## 2. Scaffold Next.js

From the repo root, create the app in a `frontend/` folder:

```bash
npx create-next-app@latest frontend \
  --typescript --tailwind --app --src-dir --eslint \
  --import-alias "@/*" --no-turbopack
```

Accept the App Router. After it runs, `cd frontend`. All remaining phases happen here.
Confirm `npm run dev` boots the default page before proceeding.

## 3. Dependencies

Install (with a one-line reason each — keep only these):

```bash
npm install @reduxjs/toolkit react-redux \
  @supabase/supabase-js \
  axios \
  react-hook-form @hookform/resolvers zod \
  lucide-react \
  sonner \
  react-markdown \
  date-fns \
  clsx tailwind-merge
```

| Package | Why |
| ------- | --- |
| `@reduxjs/toolkit` `react-redux` | State via **plain slices + async thunks** (not RTK Query — decided) |
| `@supabase/supabase-js` | Supabase Auth on the client; issues the JWT we send to Express |
| `axios` | API client with an auth interceptor to attach the Bearer JWT |
| `react-hook-form` `@hookform/resolvers` `zod` | Forms + validation; zod shared vocabulary with backend |
| `lucide-react` | Icon set (clean, Linear-adjacent) |
| `sonner` | Toasts (success/error) |
| `react-markdown` | Render job-description markdown |
| `date-fns` | Relative timestamps ("2 days ago") |
| `clsx` `tailwind-merge` | `cn()` className composition |

Dev deps (`create-next-app` brings ESLint/TS; add Prettier):
```bash
npm install -D prettier prettier-plugin-tailwindcss
```

## 4. Filesystem

Create this structure under `frontend/src` (stub files that compile; no page UI yet):

```
src/
├─ app/
│  ├─ layout.tsx                 # root: fonts + providers (Redux, Auth, Toaster)
│  ├─ globals.css                # Tailwind layers + base tokens on body
│  ├─ not-found.tsx              # branded 404 (minimal for now)
│  ├─ (auth)/
│  │  └─ login/page.tsx          # placeholder
│  ├─ (app)/                     # authed group — shares the shell layout
│  │  ├─ layout.tsx              # sidebar + topbar shell (skeleton only)
│  │  ├─ page.tsx                # dashboard (candidates) — placeholder
│  │  ├─ candidates/[id]/page.tsx
│  │  ├─ jobs/page.tsx
│  │  ├─ jobs/[id]/page.tsx
│  │  └─ interviews/page.tsx
│  └─ apply/[token]/page.tsx     # public — placeholder
│
├─ components/
│  ├─ ui/                        # primitives (empty for now: .gitkeep)
│  └─ layout/                    # sidebar/topbar (empty for now: .gitkeep)
│
├─ store/
│  ├─ index.ts                   # configureStore with all reducers
│  ├─ hooks.ts                   # typed useAppDispatch / useAppSelector
│  └─ slices/
│     ├─ authSlice.ts            # session/user/JWT
│     ├─ candidatesSlice.ts      # { list, current } + thunks (stubs)
│     ├─ jobsSlice.ts
│     ├─ interviewsSlice.ts
│     └─ uiSlice.ts              # statusFilter, searchQuery, drawer flags
│
├─ lib/
│  ├─ api/
│  │  ├─ client.ts               # axios instance + JWT interceptor + error envelope unwrap
│  │  ├─ candidates.ts           # endpoint fns (typed, stubbed to real routes)
│  │  ├─ jobs.ts
│  │  ├─ interviews.ts
│  │  ├─ offers.ts
│  │  └─ apply.ts
│  ├─ supabase/
│  │  └─ client.ts               # createBrowserClient
│  ├─ utils/
│  │  ├─ cn.ts                   # clsx + tailwind-merge
│  │  └─ date.ts                 # relativeTime()
│  └─ constants/
│     └─ statuses.ts             # STATUS → { label, colorTokens } map (from UI_GUIDE §1.2)
│
├─ types/
│  ├─ models.ts                  # Candidate, JobOpening, Interview, OfferDocument, TimelineEvent
│  └─ dto.ts                     # CandidateProfileDTO, list/response shapes, allowed_actions
│
├─ providers/
│  ├─ ReduxProvider.tsx          # 'use client' store provider
│  └─ AuthProvider.tsx           # bootstraps Supabase session → authSlice
│
└─ middleware.ts                 # protect (app) routes; redirect unauth → /login
```

Rules for the stubs:
- **`types/models.ts` mirrors `BACKEND.md` §9 exactly** — same field names, same status
  unions. This is the contract; get it right now so everything downstream is typed.
- **Slices** follow the uniform shape from our decision:
  `{ data, status: 'idle'|'loading'|'succeeded'|'failed', error }`, three `extraReducers`
  cases per thunk. Thunks may be stubbed (typed signatures, real endpoint calls wired to the
  `lib/api` fns) but must compile. Bake in the convention: **every mutation thunk refetches
  its resource on success** (leave a TODO-free wiring point, not a comment).
- **`lib/api/client.ts`** attaches `Authorization: Bearer <supabase access token>` on each
  request and unwraps the `{ data, error }` envelope, throwing typed errors on `error`.
- **`middleware.ts`** guards the `(app)` group: no valid session → redirect `/login`;
  authed user hitting `/login` → redirect `/`.

## 5. Theme wiring (tokens only — not pages)

Pull the tokens from `UI_GUIDE.md` Part 1 into the Tailwind + base layer. Dark-only.

**`tailwind.config.ts`** — extend `theme.colors` with the palette:
```
bg #0B0B0C · surface1 #141416 · surface2 #1C1C1F · border #2A2A2E · borderStrong #3A3A3F
text.primary #F4F3F1 · text.secondary #9C9AA1 · text.muted #6C6A70
brand.DEFAULT #E05020 · brand.hover #F1592A · brand.pressed #B8431C
status.* (applied/formSubmitted/interviewScheduled/offerSent/hired/rejected) with base/text/bg
```
Extend `borderRadius` (control 8px, card 12px), and set the font families to the CSS vars
from `next/font`.

**`app/layout.tsx`** — load `Inter` and `JetBrains_Mono` via `next/font/google`, expose as
CSS vars (`--font-sans`, `--font-mono`), set `<html class="dark">` and apply `--font-sans`.
Wrap children in `ReduxProvider` → `AuthProvider`, and mount `<Toaster />` (sonner).

**`app/globals.css`** — Tailwind directives; set `body { background: #0B0B0C; color:
#F4F3F1; font-feature-settings: "tnum"; }`; declare the focus-ring utility. Do **not** style
individual pages here.

`lib/constants/statuses.ts` exports the status→token map so pills read from one place.

## 6. Env & gitignore

**`.env.local.example`** (committed):
```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
NEXT_PUBLIC_API_BASE_URL=https://<your-express-host>/api/v1
```
Create a real `.env.local` from it for local boot (empty values are fine for the skeleton to
compile; the app need not fully authenticate yet). Ensure `.gitignore` covers
`node_modules`, `.next`, `.env*.local`, `out`, build artifacts. **Never commit `.env.local`.**

## 7. Verify (quality gate — must pass before pushing)

Run all of these clean:
```bash
npx tsc --noEmit          # zero type errors under strict
npm run lint              # zero eslint errors
npm run build             # production build succeeds
```
Also confirm `npm run dev` boots and every route renders its placeholder without runtime
error (visit `/login`, `/`, `/candidates/x`, `/jobs`, `/jobs/x`, `/interviews`, `/apply/x`).

Not done until: strict `tsc` clean, lint clean, `build` succeeds, no comments remain, no
unused deps, `.env.local` is gitignored, every route compiles and renders.
